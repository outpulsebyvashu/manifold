Non-linear Manifold-aware Geodesic distances Graph + MDS

Isomap

What if instead of measuring the straight-line distance between two points, you measured the shortest path along the surface the data lies on? That is the entire idea behind Isomap.

Scroll to explore ↓
The Core Idea

Why Straight Lines Fail

PCA uses Euclidean (straight-line) distances. On curved surfaces, this is completely wrong. Isomap fixes it.

🌎

Distances on a Globe

London and New York are about 5,500 km apart if you travel along the surface of the Earth. The straight-line distance through the Earth's core is shorter — but no plane can fly that path. The meaningful distance is the one that respects the surface you live on. Isomap measures distances this way: not through the air, but along the curved sheet the data occupies.

🧼

The Swiss Roll Problem

Imagine a rolled-up carpet. Two points that look close when you measure through the air might actually be very far apart along the carpet's surface. PCA sees the short straight-line distance and confuses the two ends of the roll. Isomap measures how far apart they truly are along the roll itself — then unrolls the carpet into a flat 2D layout that reflects those true distances.

The key insight: real data often lies on a manifold — a curved low-dimensional surface embedded in high-dimensional space. Euclidean distance ignores the curvature and gives wrong answers. Isomap approximates the true geodesic (surface) distance using shortest paths through a neighbourhood graph, then applies classical MDS to produce a flat embedding that preserves those distances.
The Algorithm

Three Steps of Isomap

Isomap is elegantly simple: build a graph, find shortest paths, apply MDS. Every step has a full derivation.

1
Build the Neighbourhood Graph
Connect each point to its k nearest neighbours using Euclidean distance. The edge weight between connected points is their Euclidean distance. Points that are NOT connected have no direct edge. This graph is our approximation of the manifold's local structure — close enough together that the surface is nearly flat, so Euclidean distance is a good local approximation.
G = (V, E) where
E contains edge (i,j) if j in kNN(i)
weight(i,j) = ||x_i - x_j||
Where does this come from?

The key assumption of Isomap is that on a smooth manifold, short enough distances are well-approximated by Euclidean distance. Two points close on the surface are also close in Euclidean space.

Two variants of neighbourhood:
k-NN: connect each point to its k nearest neighbours (fixed number). Most common. Sensitive to choice of k.
epsilon-ball: connect all pairs within Euclidean distance epsilon. More geometrically principled but harder to tune.
Why not just use all pairwise distances?
Because on a curved surface, the straight-line distance between two distant points cuts through the interior of the manifold — a path that doesn't exist on the surface. We need to constrain paths to stay on the surface, which is what the graph does.
💡 k controls how local vs global the geodesic estimates are
2
Compute Geodesic Distances via Dijkstra
Now we compute the shortest path between every pair of points through the graph. The shortest path distance approximates the true geodesic (surface) distance. We use Dijkstra's algorithm for each source point, giving an n×n matrix D_G of geodesic distances. This is the key step — it replaces Euclidean distances with manifold-aware distances.
D_G[i,j] = shortest path from i to j in G

Dijkstra: O(n * (n + |E|) log n)
for each of n source nodes
Where does this come from?

Dijkstra's algorithm finds the shortest weighted path from one source to all other nodes in a graph. Running it from every node gives us all-pairs shortest paths.

How Dijkstra works (one source i):
1. Initialise: dist[i]=0, dist[all others]=infinity
2. Visit unvisited node with smallest dist, call it u
3. For each neighbour v of u: if dist[u]+weight(u,v) < dist[v], update dist[v]
4. Repeat until all nodes visited
Why does this approximate geodesic distance?
Each edge in the graph is a short Euclidean step along the manifold surface (because neighbours are close). The shortest path chains these steps together — approximating the shortest path along the surface. As the graph becomes denser (more points, smaller k), the approximation improves.
💡 Dijkstra paths stay on the manifold surface — unlike Euclidean shortcuts
3
Apply Classical MDS
Given the n×n geodesic distance matrix D_G, we need to find 2D (or dD) coordinates that preserve these distances as well as possible. This is exactly the problem that Multidimensional Scaling (MDS) solves. Classical MDS converts the distance matrix to an inner product (Gram) matrix via double-centering, then takes the top eigenvectors.
B = -0.5 * H * D_G^(2) * H
H = I - (1/n) * 11^T (centering matrix)

Eigendecompose B = V Lambda V^T
Y = V_k * Lambda_k^(1/2)
Where does this come from?

MDS asks: given pairwise distances, find coordinates y_1,...,y_n such that ||y_i - y_j|| approx D_G[i,j].

Step 1 — Square the distances:
D^(2)[i,j] = D_G[i,j]^2
Step 2 — Double-centering to get inner products:
If coordinates are centred at 0, then ||y_i - y_j||^2 = ||y_i||^2 + ||y_j||^2 - 2 y_i^T y_j. We can extract the inner products B = Y Y^T from D^(2) by centering rows and columns:
B = -0.5 * H D^(2) H where H = I - (1/n)11^T
Step 3 — Eigendecompose B:
B = V Lambda V^T (B is positive semi-definite if distances are Euclidean)
Step 4 — Extract coordinates:
Y = V_k Lambda_k^(1/2) (top k eigenvectors scaled by sqrt of eigenvalues)
Then Y Y^T = V_k Lambda_k V_k^T = B_approx, giving ||y_i - y_j|| approx D_G[i,j].
💡 MDS finds coordinates whose pairwise distances match D_G as closely as possible
4
The Residual Variance Plot
How do we know if Isomap worked well, and how many output dimensions to keep? We plot the residual variance — how much of the geodesic distance information is lost at each number of dimensions. The elbow of this curve tells us the intrinsic dimensionality of the manifold.
R^2(d) = 1 - corr^2(D_G, D_Y(d))

D_Y(d) = Euclidean distances in d-dim embedding
corr = Pearson correlation coefficient
Where does this come from?

The residual variance R^2(d) measures how well the d-dimensional embedding preserves the original geodesic distances:
corr(D_G, D_Y): Pearson correlation between all pairs of geodesic distances and all pairs of embedding distances
R^2 = 1 - corr^2: residual — how much is NOT explained by the embedding
Reading the plot:
R^2 near 0: almost perfect preservation of geodesic distances
R^2 near 1: very poor preservation
The "elbow": where adding more dimensions stops helping much. This is the intrinsic dimensionality of the data manifold.
For a Swiss Roll (a 2D sheet rolled up in 3D), R^2 should drop to near 0 at d=2 and stay flat — confirming the manifold is truly 2-dimensional.
💡 The elbow of R^2 reveals the true intrinsic dimensionality of the data
5
Geodesic vs Euclidean: Side by Side
The entire power of Isomap comes down to this single comparison: geodesic distance vs Euclidean distance. On a curved manifold these are very different. PCA uses Euclidean and gets the wrong answer. Isomap uses geodesic and correctly unfolds the manifold. This step visualises exactly what changes and why it matters.
PCA uses: D_E[i,j] = ||x_i - x_j||
Isomap uses: D_G[i,j] = shortest path in G

On flat data: D_G approx D_E (same result)
On curved data: D_G >> D_E (very different)
When do they agree?

On flat, linear data (e.g., a Gaussian cloud), the shortest graph path between two points approximates the straight-line distance. On such data, Isomap and PCA give essentially the same result.
Flat data: Isomap = PCA = MDS (same embedding)
Curved manifold: Isomap unrolls correctly, PCA fails
The failure mode of Isomap:
If k is too small: the graph disconnects, and some geodesic paths become infinite
If k is too large: "short-circuit" edges jump across the manifold, corrupting geodesics
Noisy data: edges may connect distant manifold regions
Choosing k: try several values of k and look for stability in the embedding. The residual variance plot also guides this.
💡 If k is too large, short-circuit edges destroy the geodesic approximation
Reference

Key Properties of Isomap

✓ Strengths

  • Correctly unfolds curved manifolds (Swiss Roll, S-curve)
  • Global structure preserved (unlike t-SNE)
  • Deterministic: same result every run
  • Residual variance plot reveals intrinsic dimension
  • Simple and interpretable: graph + MDS
  • Can project new points (via Nystrom extension)

✗ Limitations

  • Sensitive to k: too small = disconnected graph, too large = short-circuits
  • Fails on non-convex manifolds (e.g., a torus or a holed shape)
  • O(n^2) memory for distance matrix
  • Slow: O(n^2 log n) for Dijkstra + O(n^2 d) for eigen decomposition
  • Noisy data can create incorrect graph connections

⌛ When to Use Isomap

  • Data lies on a smooth, convex manifold
  • You want to discover the true intrinsic dimension
  • Global structure matters (t-SNE distorts it)
  • Medium datasets (under ~5000 points)
  • When you need a deterministic, reproducible embedding

🌎 Real-World Uses

  • Face images (pose + lighting manifold)
  • Handwritten digit shape manifolds
  • Robotics: configuration space exploration
  • Climate: discovering modes of variability
  • Molecular conformations in drug discovery
